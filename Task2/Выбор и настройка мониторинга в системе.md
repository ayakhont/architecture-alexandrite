## Мотивация
- Без мониторинга невозможно понять, где именно застревают заказы в распределенной системе в случае ошибки или высокой нагрузки.
Мониторинг позволит быстро выявление узкие места в процессе заказов.
- При падении любого сервиса или БД бизнес теряет продажи и операционку. Алерты о падении сервисов, БД, очередей до того,
как пострадают клиенты.
- Не видно общую картину без мониторинга. Мониторинг добавит прозрачности 
для бизнеса: дашборды по воронке заказов, SLA, сбоям и скорости выполнения заказов.
- Мониторинг даст данные по нагрузке, что станет основой для масштабирования и оптимизации ресурсов.
- Релизы часто задерживаются. Мониторинг поможет выявить проблемы в новых релизах, ускорит работу QA.

## Выбор подхода к мониторингу
### RED
Для API и пользовательских сервисов:
- Shop API (создание заказа, загрузка 3D)
- CRM API (подтверждение производства, закрытие заказа)
- MES API (расчёт цены, смена статусов)

HTTP-сервисы, критичные для пользователей и бизнес-флоу заказов

### USE
Для ресурсов, где чаще всего происходят тихие деградации: CPU, диск, очереди:
- EC2-инстансы приложений
- Managed PostgreSQL
- RabbitMQ
- 3D-files storage

Раннее обнаружение деградаций до падений. Понимание, где именно узкое место: CPU, диск, сеть, коннекты к БД

### Четыре золотых сигнала
Для всей системы и бизнес-процесса заказов:
- Время от SUBMITTED до SHIPPED
- Количество заказов в статусах
- Ошибки интеграций между Shop, CRM и MES
- Насыщение очередей и БД под нагрузкой

Понимание здоровья всей системы. Связь тех.метрик с бизнес-метриками.

## Какие категории метрик и в каких частях системы
### 1. Number of requests (RPS) for Shop / CRM / MES APIs
Показывает реальную нагрузку и помогает: ловить аномалии (всплески трафика), понимать эффект релизов, 
видеть, где система горит чаще всего.

Ярлыки (labels):
- service = shop|crm|mes
- endpoint
- method
- status_code_group = 2xx|4xx|5xx
- env = dev|release|prod

### 2. Response time (latency) for Shop / CRM / MES APIs
Ключевая метрика пользовательского опыта и деградации после релизов. 
Ранний индикатор проблем с БД, очередями и внешними интеграциями.

Ярлыки:
- service = shop|crm|mes
- endpoint
- method
- env = dev|release|prod
- quantile = p50|p95|p99

### 3. Number of HTTP 500 for Shop / CRM / MES APIs
Прямой индикатор поломок флоу заказов.

Ярлыки:
- service = shop|crm|mes
- endpoint
- exception_type
- env = dev|release|prod

### 4. Number of simultaneous sessions for Shop / CRM / MES APIs
Понимание реальной одновременной нагрузки для прогнозирования масштабирования в будущем, 
отображение деградации в пиковые часы.

Ярлыки:
- service = shop|crm|mes
- env = dev|release|prod

### 5. CPU % / Memory Utilisation for Shop / CRM / MES APIs
Показатели перегруза, проблем с GC, неэффективных запросов, утечек памяти, неконтролируемого роста кэшей.

Ярлыки:
- service = shop|crm|mes
- env = dev|release|prod

### 6. Number of connections for Shop DB / MES DB
Показатель перегруза БД, который может привести к таймаутам и ошибкам.

Ярлыки:
- db = shop|mes
- env = dev|release|prod

### 7. Memory Utilisation for Shop DB / MES DB
Показывает деградацию до падений, проблемы с кэшем БД и ростом нагрузки.

Ярлыки:
- db = shop|mes
- env = dev|release|prod

### 8. Number of message in flight in RabbitMQ
Индикатор проблем в обработке заказов и статусов.

Ярлыки:
- queue
- consumer
- env = dev|release|prod

### 9. Number of dead-letter-exchange letters in RabbitMQ
Прямой сигнал потери заказов или статусов. Выявление инцидентов.

Ярлыки:
- queue
- reason
- env = dev|release|prod

## Дополнительные метрики:
### 10. Orders by status (INITIATED, SUBMITTED, PRICE_CALCULATED, …)
Главная бизнес-метрика для выявления узких мест в процессе заказов и понимания, где застревают заказы.

Ярлыки:
- status
- env = dev|release|prod

### 11. Order status transition duration
SLA по бизнес-флоу (например, из SUBMITTED в PRICE_CALCULATED).

Ярлыки:
- from_status
- to_status
- env = dev|release|prod

### 12. Failed order status transitions for Shop / CRM / MES 
Показывает поломки интеграций между Shop, CRM и MES.

Ярлыки:
- from_status
- to_status
- service = shop|crm|mes
- env = dev|release|prod

### 13. RabbitMQ consumer lag (queue backlog age)
Понимание, насколько система отстаёт от реального времени.

Ярлыки:
- queue
- env = dev|release|prod

## План действий
1. **Развернуть централизованное хранилище метрик (time-series DB)**

Создать инстанс системы хранения метрик Prometheus или managed-решение в облаке с настройкой ретенции и бэкапов.

2. **Развернуть систему визуализации и алертинга**

Поднять Grafana и централизованный алертинг, настроить интеграцию с мессенджерами команды.

3. **Инструментировать все API-сервисы (Shop, CRM, MES) RED-метриками**

Внедрить сбор RPS, latency (p95/p99), HTTP 5xx, количество сессий с едиными лейблами (service, endpoint, env).

4. **Подключить мониторинг инфраструктуры сервисов**

Настроить сбор CPU, memory, disk, network для всех инстансов приложений.

5. **Подключить мониторинг баз данных (Shop DB, MES DB)**

Настроить метрики коннектов, памяти, ошибок.

6. **Подключить мониторинг RabbitMQ как бизнес-критичной зависимости**

Настроить метрики DLQ, in-flight messages, backlog/lag и алерты на потерю сообщений.

7. **Подключить мониторинг хранилища 3D-файлов**

Отслеживать доступность, ошибки, latency и рост объёма хранилища.

8. **Внедрить бизнес-метрики по заказам и их статусам**

Собирать количество заказов по статусам и время переходов между статусами (SLA этапов).

9. **Определить SLI/SLO и настроить ключевые алерты**

Формализовать целевые значения по latency, ошибкам, задержкам обработки заказов и деградациям инфраструктуры.

10. **Создать дашборды для техкоманды и бизнеса**

Технические: RED/USE по сервисам

Бизнес: воронка заказов, застрявшие статусы, SLA

11. **Встроить мониторинг в процессы команды**

Метрики и алерты обязательны для новых фич, использовать мониторинг при релизах и инцидентах.

## Ключевые показатели насыщенности
1. **CPU Saturation (Shop / CRM / MES)**

Метрика: CPU %

Порог:

- Warning: > 70% в течение 5 минут
- Critical: > 85% в течение 3 минут

Почему именно это:
CPU — первый лимит для синхронных API. При высоком CPU резко растёт latency и количество 5xx.

Что делаем при превышении:
- Warning: завести тикет в бэклог техдолга
- Critical: алерт в on-call
- Повторяется: план на автоскейлинг

2. **Memory Saturation (Shop / CRM / MES)**

Метрика: Memory Utilisation %

Порог:

- Warning: > 75% в течение 5 минут
- Critical: > 90% в течение 3 минут

Почему именно это:

Высокая загрузка памяти может привести к OOM и падению сервисов, что критично для бизнес-флоу заказов.

Что делаем при превышении:
- Warning: тикет на оптимизацию/поиск утечек
- Critical: on-call + рестарт инстанса
- Повторяется: анализ memory leak / heap dump, увеличение ресурсов или автоскейлинг

3. **Насыщение коннектов к БД (Shop DB, MES DB)**

Метрика: Number of DB connections / Max connections
Порог:

- Warning: > 70% пула
- Critical: > 85% пула

Почему:

Исчерпание пула приводит к таймаутам API и 500 ошибкам у пользователей.

Реакция:

- Warning: тикет на оптимизацию пула / connection reuse
- Critical: on-call + временно увеличить пул / лимит в managed DB
- Повтор: профилирование запросов, connection leaks

4. **Насыщение очередей RabbitMQ**

Метрика: Number of messages in flight / Queue capacity

Порог:
- Warning: > 70% в течение 5 минут
- Critical: > 85% в течение 3 минут

Почему:

Очереди — критичная часть флоу заказов. Их насыщение приводит к задержкам и потере заказов.

Реакция:

- Warning: тикет на оптимизацию потребления / увеличение ресурсов
- Critical: on-call + временно увеличить ресурсы RabbitMQ
- Повтор: анализ узких мест в обработке, оптимизация кода потребителей

5. **DLQ Saturation (потеря сообщений)**

Метрика: Number of messages in DLQ / Total messages

Порог:
- Warning: рост > 0
- Critical: рост > 10 за 5 минут

Почему:

Появление сообщений в DLQ — прямой сигнал потери заказов или статусов, что критично для бизнеса.

Реакция:
- Warning: тикет на анализ причин ошибок
- Critical: on-call + срочный анализ и исправление проблемы
- Повтор: анализ корневых причин, оптимизация кода, добавление ретрай механизма
